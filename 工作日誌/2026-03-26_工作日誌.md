## 今日目標

將原本散落的個別 HTML 小工具，整合成一個統一的「小黑工具箱」應用程式，並新增 AI 去背功能，最終打包成可一鍵啟動的 `.exe` 執行檔。

## 完成項目

### 1. 架構規劃與技術決策

- 討論了「全部改成 Python」vs「混合架構」的優劣
- 最終決定採用 **Python Flask 後端 + HTML 前端** 的混合架構：
  - 純前端能搞定的工具（PNG 轉 ICO、文字轉檔）→ 保留 HTML/JS 實作，不浪費時間重寫
  - 需要 AI 運算的工具（去背）→ 交給 Python 後端處理
  - Python 負責整合所有工具、提供統一入口、處理 API 請求

### 2. 建立 Flask 主程式（app.py）

- 建立 Flask 應用程式作為本地 web server
- 設計路由結構：
  - `/` → 工具箱首頁
  - `/tool/bg-remover` → AI 去背工具
  - `/tool/png-to-ico` → PNG 轉 ICO 工具
  - `/tool/text-converter` → 文字轉檔工具
  - `/api/remove-bg` → 去背 API 端點（POST）
- 實作自動開啟瀏覽器功能（啟動後自動跳轉到 `http://127.0.0.1:5000`）
- 處理 PyInstaller 打包後的路徑問題（`sys._MEIPASS` 對應 `_internal` 目錄）
- 設定 `U2NET_HOME` 環境變數，確保打包後模型能被正確載入

### 3. 設計統一 Base Template（base.html）

- 建立 Jinja2 共用模板，所有工具頁面都繼承自此
- 統一的深色主題設計，包含：
  - **頂部導航列**：玻璃擬態效果（glassmorphism）、模糊背景、各工具快速跳轉
  - **動態背景**：漸層光暈 + 細格線網格，營造科技感
  - **品牌標識**：「小黑工具箱」logo 搭配漸層色
  - **離線標示**：右上角顯示「完全離線運作」提示
  - **統一頁腳**：隱私安全聲明
- 定義全域 CSS 變數、動畫效果、按鈕樣式、滾動條樣式
- 預留 `{% block %}` 給各子頁面擴展

### 4. 工具箱首頁（index.html）

- Hero 區塊：大標題漸層文字「小黑的私人工具箱」
- 標語徽章：「完全離線 · 隱私安全 · 一鍵啟動」
- 三張工具卡片，每張都有：
  - 漸層色圖示（紫色=AI 去背、藍色=PNG 轉 ICO、綠色=文字轉檔）
  - 工具分類標籤（AI / 圖片 / 文件）
  - 功能簡介
  - 技術標籤（如「U2-Net 模型」「本地推理」等）
  - hover 動畫：上浮 + 邊框漸層光暈 + 箭頭滑入
- 「更多工具即將推出」預留區塊，方便日後擴充
- 底部統計列：3 個工具 / 100% 離線 / 零資料外洩

### 5. AI 智慧去背工具（bg_remover.html + API）

- **前端介面：**
  - 左側上傳區：支援拖曳上傳 + 點擊選擇，支援 PNG/JPG/WebP
  - 右側結果區：去背前後的**對比滑桿**（可拖曳左右比較）
  - 棋盤格背景顯示透明區域
  - 處理中動畫：旋轉光環 + 提示文字
  - 下載按鈕：一鍵下載去背後的 PNG，自動命名為「原檔名_去背.png」
  - 品質徽章：U2-Net 深度學習 / 100% 離線 / 隱私安全
- **後端 API（`/api/remove-bg`）：**
  - 接收上傳的圖片（FormData）
  - 使用 `rembg` 套件 + U2-Net ONNX 模型進行推理
  - 回傳 base64 編碼的去背結果
  - 錯誤處理：套件未安裝提示、處理失敗提示

### 6. PNG 轉 ICO 工具（png_to_ico.html）

- 基於原有的 `PNG轉ICO檔案1.txt` 重構，融入統一框架

- 核心邏輯保持不變：Canvas 縮放 → PNG Blob → ICO 二進位打包

### 7. 文字轉檔工坊（text_converter.html）

- 基於原有的 `小黑文字轉檔工具1.txt` 完整移植

  - 格式互轉邏輯（表格資料、結構化資料、標記語言、純文字四大類型）

## 追加修復（同日稍晚）

### BUG 修復：瀏覽器重複開啟

- **問題：** 使用打包好的 exe 時，每次操作（例如點擊 AI 去背）都會重複開啟新的瀏覽器分頁，瘋狂開不停
- **原因：** PyInstaller 在 Windows 上打包後，子進程會重複執行 `__main__` 區塊，導致 `open_browser()` 被反覆觸發
- **修正：**
  1. 在程式最開頭加入 `multiprocessing.freeze_support()`，阻止子進程重複執行 main
  2. 加入 `_browser_opened` 全域旗標，確保 `open_browser_once()` 只會執行一次
  3. 測試等待 10 秒確認不再重複開啟

### BUG 修復：rembg 套件未安裝錯誤

- **問題：** 打包後的 exe 執行 AI 去背時跳出「rembg 套件未安裝，請執行 pip install rembg」
- **修正：**
  1. 改為啟動時背景預載入 rembg（`preload_rembg()`），不再用 lazy import
  2. 加入自動安裝機制：若未安裝則自動 `pip install rembg onnxruntime`
  3. API 端也加入 fallback：如果預載入還沒完成，會即時嘗試載入

### 新增：自訂 exe 圖示

- 小黑用工具箱的 AI 去背 + PNG 轉 ICO 功能，自製了 `app_icon2.ico`
- 更新 `build_exe.spec` 將此 icon 嵌入 exe
- 注意：中文路徑會導致 PyInstaller icon 嵌入失敗，需先複製到無中文路徑再打包

### 仍未解決：瀏覽器重複開啟

- 雖然加了 `multiprocessing.freeze_support()` 和 `_browser_opened` 旗標，小黑實測打包版 exe 使用 AI 去背時**仍然會一直跳出新瀏覽器視窗**
- 推測 `freeze_support()` 不足以完全阻止問題，可能原因：
  - rembg / onnxruntime 內部使用了 multiprocessing 產生子進程，每個子進程都會重新載入 app.py 並觸發 `open_browser`
  - `_browser_opened` 全域變數在子進程中會被重置（因為是獨立的記憶體空間）
- **下次需要嘗試的修法：**
  1. 用檔案鎖（lock file）或 port 偵測來判斷是否已有實例在運行，而非用全域變數
  2. 把 `open_browser` 完全移出 `__main__`，改用其他機制（例如只在 Flask 第一次收到 request 時開啟）
  3. 或者用 `os.environ` 設一個環境變數旗標（環境變數會被子進程繼承）
